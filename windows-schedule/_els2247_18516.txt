## PASSED: TC1 — Create a booking with Guest Contact via Excel Import (the only entry path in this release)

**Steps**

1. Open the Import Booking Excel template (the one that has the `GuestContact` column).
2. Fill in one row with all the mandatory fields (ChannelId, HotelId, dates, room/rate IDs, contact person, guest names, total amount, etc. — same fields ops uses today).
3. Also fill:

* `Comment01` = `Late check-in around 23:00`

* `GuestContact` = `Please call the guest at +82-10-1234-5678 / john@example.com`

1. Save and upload the file on admin → _Create Booking_ → _Import Booking_.
2. Wait for the import-result email and confirm the row imported successfully.
3. Note down the resulting booking item code for the next TCs.

**Expected**

* Import succeeds — the row shows green / success in the result email.
* The booking is searchable on admin under that channel.
* (If the `GuestContact` column is left empty for a different row, that row also imports successfully — Guest Contact is optional.)

With Guest contact: K26062910002H01

Without Guest contact: K26062910003H01

## PASSED: TC6 — Old bookings & default behaviour are not affected (regression)

**Steps**

1. Open a few existing bookings created **before** this change is deployed (no Guest Contact ever entered).
2. Check the Booking Detail page on admin, the vendor extranet detail page, and the seller extranet detail page for those bookings.
3. Trigger a "Resend reservation sheet" on one of these old bookings.
4. Also import one row through TC1's flow but **leave the \`GuestContact\` column empty** to simulate an ops user who doesn't use the new column.

**Expected**

* For all old bookings: no Guest Contact row appears anywhere; the Special Request inline summary and textarea behave exactly as before; the hotel email layout is unchanged.
* For the new-but-empty import: the booking imports normally and no Guest Contact row is rendered — Guest Contact is fully optional.
